## 重跑

```powershell
npm ci
npm test
npm run format:check
npm run build
npm run verify:market-layout
docker compose up -d --build --remove-orphans
docker compose exec -T api npm run verify:db
docker compose exec -T api npm run verify:worker
npm run verify
```

另開終端執行 `npm run dev`，再執行 `npm run verify:browser`。瀏覽器腳本需要本機Chrome，預設測試5173；改測預覽時先啟動 `npm run preview`，再設定BASE_URL為http://127.0.0.1:4173。

設定WEB_BASE_URL後，verify_stack.js也會檢查獨立前端入口及其資源。API_BASE_URL用於變更API驗證位址。瀏覽器驗證會操作運行中的平台，可能觸發按需資料工作；不刪除資料庫。

資料庫測試 `tests/integration.database.js` 不由 `npm test` 自動執行。使用容器指令可取得Compose內的DATABASE_URL，無需公開PostgreSQL埠；在本機執行 `npm run verify:db` 時須提供可達的專用測試連線與CREATE／DROP SCHEMA權限。測試中斷可能留下 `stock_audit_*` schema，不能未核對就刪除其他schema。

API與postgres重建／啟動後健康，scheduler程序運行；`verify:worker`核對1個排程鎖持有者，當次running心跳3秒。`/health`只代表API及DB可連線；來源狀態仍需檢查工作結果及來源時間。正式後端依賴 `npm audit --omit=dev` 本次回報0個已公告問題，不代表程式或正式部署已完成全面安全驗證。

## 實際限制

驗證不代表來源即時、完整全市場、未來預測有效或實盤可成交。分鐘／分點／基金依來源權限，集保免費接口只有最新週，法人目標需授權資料。財務選單不代表完全複製外部平台會員資料，落差見 [FINANCIAL_PARITY_AUDIT.md](FINANCIAL_PARITY_AUDIT.md)。

正式對外HTTPS、存取控制、主機程序管理、Nginx範例與完整備份還原演練，需在實際部署環境配置及驗證。本次為本機Compose與Vite驗證，未部署遠端虛擬主機。
